# Problem Framing Gate

## Purpose

This gate ensures that the research problem has been correctly framed before
any investigation begins. A poorly framed problem leads to wasted effort,
irrelevant findings, and misleading conclusions. Every research task must
pass this gate before proceeding to search planning or evidence gathering.

## Gate Question

**Is the problem correctly framed?**

The research problem must be stated in a way that is specific, answerable,
and aligned with the requestor's actual intent. Ambiguity at this stage
compounds into larger errors downstream.

## Pass Criteria

1. The problem statement is written as a clear, specific question or set of questions.
2. The requestor's underlying intent has been identified and confirmed, not just the surface-level ask.
3. Key terms and concepts in the problem statement are explicitly defined to avoid ambiguity.
4. The scope of the problem is bounded with explicit inclusions and exclusions.
5. Success criteria are defined so the research team knows what a complete answer looks like.
6. Assumptions underlying the framing are stated and flagged for validation.
7. The problem is decomposed into sub-questions where appropriate.
8. The expected output format and depth are agreed upon with the requestor.
9. Domain context is identified so the right expertise can be applied.
10. Known constraints (time, access, data availability) are documented.
11. The problem framing has been reviewed by at least one other squad member.
12. Prior research or existing knowledge on this problem has been checked for relevance.

## Fail Actions

- If the problem statement is vague, return to the requestor for clarification before proceeding.
- If key terms are undefined, draft definitions and get explicit confirmation.
- If the underlying intent is unclear, conduct a brief intent-discovery interview.
- If assumptions are unstated, enumerate them and flag each for validation during research.
- If the scope is unbounded, propose boundaries and get agreement before moving forward.
- If success criteria are missing, draft criteria and confirm with the requestor.
- If the problem cannot be decomposed, escalate to a senior researcher for guidance.
- Document all fail reasons in the research log for traceability.
- Do not proceed to the search-plan stage until all criteria are met.
