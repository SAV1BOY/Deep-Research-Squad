# Chief Scope Approval Gate

## Purpose

Ensure the research scope has been explicitly approved and bounded before
substantive work begins. Prevents scope creep, wasted cycles, and delivery
of research that misses the requester's actual need.

## Gate Question

**Is the scope approved, clearly delimited, and agreed upon by all
stakeholders?**

## Prerequisites

- Scope document produced by Scope Agent with boundaries, inclusions,
  and exclusions.
- Requester has reviewed the proposed scope statement.
- Architect has confirmed the scope is executable within resource constraints.
- Time and depth budget have been estimated.

## Pass Criteria

1. Scope document contains explicit IN-scope and OUT-of-scope sections.
2. Geographic, temporal, and domain boundaries are stated.
3. The number of sub-questions is between 3 and 12 (manageable set).
4. Each sub-question maps to at least one research layer.
5. Requester has acknowledged or signed off on the scope.
6. Estimated delivery time fits within the stated deadline.
7. No open ambiguities flagged by any agent remain unresolved.

## Fail Actions

- If boundaries are vague: return scope to Scope Agent with specific
  clarification requests.
- If sub-questions exceed 12: force prioritization or split into phases.
- If requester has not acknowledged: hold research start until sign-off
  or 24-hour auto-proceed with logged assumption.
- If deadline is unachievable at requested depth: propose phased delivery
  (interim + final).

## Escalation Rules

- Escalate if requester and Scope Agent cannot agree on boundaries after
  two revision rounds.
- Escalate if scope involves cross-organizational data requiring access
  permissions not yet granted.
- Escalate if the scope materially changed after research began (mid-stream
  scope change requires Chief re-approval).
