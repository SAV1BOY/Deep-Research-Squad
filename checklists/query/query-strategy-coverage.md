# Query Strategy Coverage Gate

## Purpose

Ensure the search strategy covers all investigative trails before queries
are executed. A narrow strategy risks missing critical evidence available
through alternative search paths.

## Gate Question

**Does the search strategy cover all viable investigative trails?**

## Prerequisites

- Sub-questions finalized and approved.
- Source plan from Architect reviewed.
- Known search platforms and databases identified.
- Prior search results (if any) reviewed for gaps.

## Pass Criteria

1. Each sub-question has at least 2 distinct search strategies planned.
2. Strategies span multiple platforms (web, academic, government, social,
   specialized databases).
3. Forward and backward citation chasing is included for key papers.
4. Named entities (people, organizations, products) have dedicated searches.
5. Temporal variants are planned (searching across different date ranges).
6. At least one exploratory/serendipity strategy is included (broader
   terms, adjacent domains).
7. Strategy document maps each trail to the sub-question it serves.

## Fail Actions

- If a sub-question has fewer than 2 strategies: add additional trails.
- If only one platform is used: expand to at least 3 platforms.
- If no citation chasing planned: add forward and backward passes for
  the most relevant initial finds.
- If named entity searches missing: add them for all key entities.
- If no exploratory strategy exists: add one broad-scope search trail.

## Escalation Rules

- Escalate if the topic is so niche that standard search strategies yield
  no results after initial probing.
- Escalate if access to critical search platforms is restricted.
- Escalate if the query volume would exceed rate limits or cost budgets.
