# Data Base Rate Check

## Purpose

Ensure that base rates are properly accounted for in data interpretation.
Ignoring base rates is one of the most common analytical errors, leading to
dramatically wrong probability assessments and conclusions.

## Gate Question

**Have base rates been identified and properly applied in the analysis?**

## Prerequisites

- Claims involving probability, frequency, or prevalence identified.
- Population-level statistics available for the relevant domain.
- Conditional probabilities distinguished from unconditional ones.
- Bayesian reasoning framework accessible.

## Pass Criteria

1. Base rates are stated for every claim involving likelihood or frequency.
2. Conditional probabilities are not confused with unconditional ones
   (prosecutor's fallacy avoided).
3. Sample statistics are compared to population base rates.
4. Rare events are contextualized against their base rate of occurrence.
5. Risk ratios and relative changes are accompanied by absolute numbers.
6. "X% increase" claims specify the base from which the increase is
   measured.
7. Base rate sources are cited and their quality assessed.

## Fail Actions

- If base rates are missing: find and include the relevant population
  statistics.
- If conditional and unconditional probabilities are confused: correct
  the framing.
- If relative changes lack absolute context: add the absolute numbers.
- If rare events are presented without base rates: add the context.
- If base rate sources are uncited: locate and cite them.

## Escalation Rules

- Escalate if reliable base rate data does not exist for the domain.
- Escalate if base rate analysis reveals that a central claim is
  misleading when properly contextualized.
- Escalate if Bayesian reasoning is required but exceeds agent
  analytical capability.
