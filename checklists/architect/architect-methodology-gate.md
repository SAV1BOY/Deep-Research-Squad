# Architect Methodology Gate

## Purpose

Confirm that the chosen research methodology matches the question type and
will produce valid, defensible results. Prevents method-question mismatch
that undermines research quality.

## Gate Question

**Is the selected methodology correct for this question type and context?**

## Prerequisites

- Question type classified (factual, causal, comparative, predictive,
  evaluative, exploratory).
- Research design with layers and agents assigned.
- Architect has reviewed available methodology templates.
- Domain constraints (quantitative data availability, time series presence,
  expert access) assessed.

## Pass Criteria

1. Methodology matches question type (e.g., comparative analysis for
   comparison questions, causal tracing for "why" questions).
2. Data requirements of the methodology can be met with available sources.
3. The methodology has a clear protocol the executing agents can follow.
4. Analytical framework is specified (SWOT, Porter's, PESTEL, etc.) when
   the question warrants structured analysis.
5. Methodology accounts for known biases in the source landscape.
6. Triangulation approach is defined (how multiple evidence streams converge).
7. The methodology is proportionate to the stakes and depth tier.

## Fail Actions

- If methodology does not fit question type: select an appropriate method
  from the template library.
- If data requirements cannot be met: adapt the methodology or flag the
  limitation to Chief Agent.
- If no protocol exists: Architect must write a step-by-step procedure
  before agents begin.
- If bias accounting is absent: add explicit bias mitigation steps.

## Escalation Rules

- Escalate if the question requires a methodology not in the current
  template library.
- Escalate if domain experts are needed to validate the methodology choice.
- Escalate if agents disagree on the appropriate methodology.
