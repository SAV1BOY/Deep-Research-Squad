# Scope Feasibility Gate

## Purpose

Confirm that the approved scope is actually researchable given available
resources, time, source access, and agent capabilities. Prevents commitment
to research that cannot be completed.

## Gate Question

**Is this scope researchable with the resources and time available?**

## Prerequisites

- Full scope document with sub-questions and boundaries.
- Resource allocation estimate from Architect Agent.
- Source availability assessment from Source Agent.
- Deadline and depth tier confirmed by Chief Agent.

## Pass Criteria

1. Each sub-question has at least one known accessible source.
2. Total estimated effort fits within the deadline with 20% buffer.
3. No sub-question requires data that is classified, deleted, or
   demonstrably unavailable.
4. Required languages are within agent capabilities or translation
   tools are available.
5. Required quantitative analysis is within agent computation abilities.
6. No legal or ethical barriers exist to accessing needed information.
7. Fallback plans exist for the top 3 feasibility risks.

## Fail Actions

- If a sub-question has no accessible source: replace it, narrow it,
  or flag it as unanswerable with explanation.
- If effort exceeds deadline: reduce scope or negotiate deadline extension.
- If data is unavailable: document the gap and adjust expectations.
- If language barriers exist: engage translation tools or narrow geographic
  scope.
- If legal barriers exist: exclude the blocked sub-question and note the
  limitation.

## Escalation Rules

- Escalate if more than 30% of sub-questions have feasibility concerns.
- Escalate if the research requires access to systems, databases, or
  experts not currently available.
- Escalate if feasibility issues are discovered mid-research after
  significant effort has been invested.
- Escalate if legal review is needed before proceeding.
