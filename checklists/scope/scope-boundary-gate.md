# Scope Boundary Gate

## Purpose

Confirm that clear boundaries have been set around the research so agents
know exactly what is included and excluded. Prevents scope creep and ensures
focused, efficient investigation.

## Gate Question

**Are the research limits clear, documented, and agreed upon?**

## Prerequisites

- Problem framing gate passed.
- Requester's constraints (time, geography, domain) collected.
- Initial sub-question decomposition available.
- Architect's feasibility input received.

## Pass Criteria

1. Temporal boundaries are explicit (date range or era specified).
2. Geographic boundaries are stated (global, regional, country-specific).
3. Domain boundaries are defined (which sectors, disciplines, or fields).
4. Population or entity scope is clear (which organizations, groups, etc.).
5. Depth limit is set (survey-level, standard analysis, deep investigation).
6. Exclusions are listed explicitly (what is deliberately NOT covered).
7. Boundary rationale is documented (why these limits and not others).

## Fail Actions

- If any boundary dimension is missing: add it with a reasonable default
  and flag for requester approval.
- If boundaries are contradictory: resolve and document the resolution.
- If boundaries are so wide the research is infeasible: propose narrowing
  with justification.
- If boundaries are so narrow the question cannot be meaningfully answered:
  propose widening.
- If exclusions are not listed: require at least 3 explicit exclusions.

## Escalation Rules

- Escalate if the requester insists on boundaries that make the research
  infeasible within the deadline.
- Escalate if boundaries cross jurisdictional or legal lines requiring
  compliance review.
- Escalate if boundary disagreements persist between requester and Scope
  Agent after one revision.
