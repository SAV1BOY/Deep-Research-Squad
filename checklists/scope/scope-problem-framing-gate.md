# Scope Problem Framing Gate

## Purpose

Ensure the research problem is clearly and correctly framed before any
investigation begins. A poorly framed problem leads to irrelevant research
and wasted effort.

## Gate Question

**Is the problem well-defined, unambiguous, and framed for actionable
research?**

## Prerequisites

- Original request text from the requester available.
- Any clarifying Q&A exchanges documented.
- Domain context sufficient to interpret terminology.
- Intended use of the research output understood.

## Pass Criteria

1. The core question is stated in a single, clear sentence.
2. Key terms are defined or linked to accepted definitions.
3. The question distinguishes between what is known and what is unknown.
4. Implicit assumptions are surfaced and stated explicitly.
5. The framing avoids loaded language or embedded conclusions.
6. The question type is classified (factual, causal, comparative,
   predictive, evaluative).
7. Success criteria are defined: what would a good answer look like?

## Fail Actions

- If core question is ambiguous: rewrite and seek requester confirmation.
- If key terms are undefined: produce a working glossary.
- If assumptions are hidden: list them and validate with requester.
- If framing is biased: rewrite in neutral language and flag the change.
- If success criteria are missing: propose criteria and confirm.

## Escalation Rules

- Escalate if the requester cannot articulate the core question after
  two clarification rounds.
- Escalate if the problem framing reveals the question is outside the
  squad's domain competence.
- Escalate if the framing involves ethically sensitive topics requiring
  human oversight.
