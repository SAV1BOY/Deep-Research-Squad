# Slack Research Update Delivery Guide

## Purpose

This guide defines how to share research updates on Slack. Slack is a
high-velocity, low-attention channel. Updates must be scannable, self-contained,
and link to deeper content when available.

## When to Use Slack Updates

- Sharing interim findings before a full deliverable is ready.
- Alerting stakeholders to time-sensitive intelligence.
- Providing status updates on ongoing research.
- Distributing completed deliverables with a summary.

## Structure: The Slack Research Block

Use this template for all research updates:

```
[EMOJI] Research Update: [Topic in 5 Words or Fewer]

Bottom line: [One sentence finding or status]

Key points:
- [Point 1]
- [Point 2]
- [Point 3 if needed]

Confidence: [High / Medium / Low]
Sources: [N sources, Tier X-Y]

[Link to full analysis if available]
[Thread for questions]
```

### Emoji Guide

| Emoji | Meaning                          |
|-------|----------------------------------|
| 🔍    | New research finding             |
| ⚠️    | Urgent or time-sensitive finding |
| 📊    | Data update or metric change     |
| ✅    | Research complete / delivered     |
| 🔄    | Status update / in progress      |
| 🚩    | Escalation or risk flag          |

## Writing Rules for Slack

1. **One message, one topic.** Do not combine multiple findings.
2. **Thread for discussion.** Put the update in the main channel, discussion in thread.
3. **No walls of text.** Maximum 8 lines in the main message.
4. **Bold the bottom line.** It should be the first thing scanned.
5. **Link, do not paste.** Reference the full document, do not copy sections.

## Channel Selection

| Content Type             | Channel                          |
|--------------------------|----------------------------------|
| Completed deliverable    | #research-deliverables           |
| Interim finding          | #research-wip                    |
| Urgent alert             | #research-alerts + tag owners    |
| Status update            | #research-standup                |
| Cross-squad delivery     | Receiving squad's research channel|

## Urgency Protocol

For time-sensitive findings:
1. Post to #research-alerts.
2. Tag the relevant decision-maker directly.
3. Include a deadline: "Decision needed by [date]."
4. Follow up in DM if no response within 2 hours.

## Threading Best Practices

- The parent message is the summary. Never edit it to add information.
- Use the thread to add supporting detail, answer questions, or update findings.
- Pin the parent message if it is relevant for more than 48 hours.
- Archive threads into the formal deliverable when the research is complete.

## Common Mistakes

- Writing a Slack message that reads like an email.
- Posting findings without confidence levels.
- Not linking to the source document.
- Using #general for research updates.
- Posting sensitive findings in public channels.

## Quality Check

- Is the message scannable in 10 seconds?
- Is the bottom line in the first line?
- Is the confidence level stated?
- Is there a link to the full analysis?
- Is it posted in the correct channel?
