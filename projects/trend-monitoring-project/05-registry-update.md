# 05 - Registry Update

## Purpose

This phase ensures all signals, trends, and monitoring artifacts from
the Trend Monitoring project are captured in permanent registries.
Trend data is inherently temporal, so registry entries must include
timestamps and expiration indicators.

## Registry Updates Required

### Source Registry
- Log all signal sources identified during monitoring
- Include automated feeds, publications, and expert networks
- Rate each source for signal quality and timeliness
- Flag sources that proved unreliable or noisy
- Note discovery method for each source (search, referral, automated)

### Claim Registry
- Register all trend claims with directional indicators
- Include: trend name, direction, strength, time horizon
- Record the evidence basis for each trend assertion
- Flag trends that are speculative vs. evidence-supported
- Include counter-indicators where they exist

### Insight Registry
- Capture pattern-level insights from signal analysis
- Document emerging themes across multiple signals
- Record convergence or divergence of related trends
- Note second-order implications identified
- Link to specific signals and sources

### Hypothesis Registry
- Document all trend hypotheses generated
- Include: hypothesis statement, supporting signals, test criteria
- Record confidence level and key assumptions
- Define what would confirm or disconfirm each hypothesis
- Set review dates for hypothesis reassessment

### Domain Registry
- Update domain landscape based on monitoring findings
- Record new entrants, exits, or pivots observed
- Document shifts in domain boundaries or definitions
- Note cross-domain trends that span multiple registries

## Process

### Step 1: Signal Inventory
Compile all signals identified during the monitoring period.
Categorize by strength (strong, moderate, weak) and domain.

### Step 2: Trend Synthesis
Group related signals into trend narratives.
Each trend should reference at least three independent signals.

### Step 3: Registry Entry Creation
For each trend and its supporting signals:
- Create source entries for all signal origins
- Create claim entries for trend assertions
- Create insight entries for pattern-level findings
- Create hypothesis entries for forward-looking projections

### Step 4: Temporal Metadata
Add to every entry:
- First observed date
- Last confirmed date
- Suggested review date
- Confidence decay rate (how quickly this becomes stale)

### Step 5: Quality Check
- Are all signals traced to their source?
- Are trend claims supported by multiple signals?
- Do hypotheses have clear confirmation criteria?
- Are temporal metadata fields complete?
- Is the monitoring plan updated for the next cycle?

## Completion Criteria

Complete when all trends are registered with temporal metadata and
the monitoring plan is updated for the next observation cycle.
