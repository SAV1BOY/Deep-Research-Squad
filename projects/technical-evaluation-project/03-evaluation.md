# Phase 3: Detailed Evaluation

## Purpose
Conduct rigorous, hands-on evaluation of each shortlisted candidate
against the weighted requirements framework. Generate objective,
evidence-based scores for every evaluation criterion.

## Inputs
- Shortlisted candidates from Phase 2
- Weighted evaluation criteria from Phase 1
- Scoring methodology and rubric
- Test environments and evaluation licenses
- Reference architecture for integration testing

## Process Steps
1. Set up evaluation environments for each candidate.
2. Execute functional requirement tests per the rubric.
3. Run performance benchmarks under realistic load conditions.
4. Assess security posture: vulnerabilities, auth, encryption.
5. Test integration points with existing architecture.
6. Evaluate developer experience: docs, APIs, tooling, support.
7. Assess operational requirements: monitoring, deployment, backup.
8. Interview reference customers or community members.
9. Score each candidate on every criterion using the rubric.

## Quality Gates
- [ ] All candidates are tested in comparable environments
- [ ] Every evaluation criterion has an evidence-backed score
- [ ] Performance benchmarks use realistic, not synthetic, loads
- [ ] Security assessment covers OWASP top 10 at minimum
- [ ] Integration testing uses actual (not mocked) connections
- [ ] Reference checks include at least two external sources
- [ ] Scores are reviewed by a second evaluator for bias

## Outputs
- Completed scorecards per candidate
- Performance benchmark results
- Security assessment reports
- Integration test results
- Developer experience evaluation notes
- Reference check summaries
- Updated claim registry entries
