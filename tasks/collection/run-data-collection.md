# Run Data Collection

## Purpose
Execute focused data collection to gather specific data points, datasets, or quantitative information required by other research tasks, ensuring data quality, consistency, and proper documentation.

## When to Use
- When a research task requires specific quantitative data not yet collected
- For populating comparison frameworks, benchmarks, or evidence tables
- When building datasets for analysis, modeling, or visualization
- To fill identified data gaps in an ongoing research effort
- For periodic data refresh cycles on tracked metrics

## Agents Involved
- **Lead**: Data Collector
- **Executing**: Deep Researcher, Source Curator
- **Supporting**: Domain Analyst
- **Validating**: Evidence Validator

## Inputs
- Data requirements specification (what data points, format, granularity)
- Target sources and collection methods
- Data quality requirements (accuracy, recency, completeness)
- Schema or template for data capture
- Timeline and priority for collection

## Steps
1. Review data requirements and clarify any ambiguities with the requesting task
2. Design the data collection schema with field definitions and validation rules
3. Identify and prioritize data sources for each required data point
4. Execute collection from primary sources, recording provenance for each datum
5. Validate collected data against quality rules (format, range, consistency)
6. Flag and investigate data points that fail validation checks
7. Fill gaps by expanding to secondary and tertiary sources
8. Cross-reference key data points across multiple sources for accuracy
9. Resolve discrepancies between sources and document resolution rationale
10. Normalize data formats, units, and scales for consistency
11. Document collection methodology, sources, and any limitations
12. Deliver the completed dataset with quality assessment and metadata

## Quality Gates
- All required data points are collected or gaps are explicitly documented
- Each data point has documented provenance (source, date, method)
- Data passes defined validation rules for format, range, and consistency
- Key data points are cross-referenced against at least two sources
- Discrepancies are resolved and resolution rationale is documented
- Dataset includes metadata describing collection methodology and limitations

## Outputs
- Completed dataset in the specified format and schema
- Data provenance log (source, date, method per data point)
- Data quality assessment report
- Gap analysis (missing data points with explanation)
- Discrepancy resolution log
- Collection methodology documentation

## Estimated Effort
- **Small dataset (10-20 data points)**: 1-2 hours
- **Medium dataset (20-50 data points)**: 2-4 hours
- **Large dataset (50+ data points)**: 4-10 hours
