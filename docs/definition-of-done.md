# Definition of Done

## Purpose

This document defines when a research deliverable is considered complete.
A deliverable is "done" when it meets all applicable criteria below.
Partial completion is not done. Aspirational completion is not done.

## Universal Criteria (All Deliverables)

Every deliverable, regardless of format, must satisfy:

### Evidence and Confidence

- [ ] Every factual claim is cited with source attribution.
- [ ] Every finding is tagged with a confidence level: [CONFIRMED], [PROBABLE], [HYPOTHESIS], or [UNKNOWN].
- [ ] Evidence tiers are correctly assigned per `evidence-policy.md`.
- [ ] No Tier 4-5 findings are presented with Tier 1-2 language.

### Transparency

- [ ] Methodology is described or referenced.
- [ ] Limitations are explicitly disclosed.
- [ ] Gaps in evidence are identified.
- [ ] Assumptions are stated.

### Quality

- [ ] The deliverable has passed all applicable quality gates.
- [ ] Red team review has been completed for major conclusions.
- [ ] Citations have been audited by the Evidence Auditor.
- [ ] The Research Director has signed off.

### Audience Calibration

- [ ] The deliverable matches the audience's depth level.
- [ ] The tone matches the selected profile.
- [ ] Technical terms are defined or translated as appropriate.
- [ ] The format matches the channel (deep dive, brief, Slack, presentation).

## Format-Specific Criteria

### Deep Dive

- [ ] Executive summary can stand alone.
- [ ] Full methodology section is included.
- [ ] Findings are organized with evidence per section.
- [ ] Appendices include full source list and supporting data.
- [ ] Document length: 10-30 pages.

### Executive Brief

- [ ] Follows the 1-3-1 format (bottom line, 3 evidence points, recommendation).
- [ ] Fits on one page or less.
- [ ] Links to full analysis.
- [ ] Recommended action is specific and time-bound.

### Synthesis

- [ ] All five synthesis layers are present (convergence, divergence, integration, implications, gaps).
- [ ] Source attribution is maintained in integrated sections.
- [ ] Creates understanding beyond what individual sources provide.

### Slack Update

- [ ] Follows the Slack research block template.
- [ ] Scannable in 10 seconds.
- [ ] Confidence level is stated.
- [ ] Link to full analysis is included.

### Presentation

- [ ] BLUF on slide 2.
- [ ] One finding per slide.
- [ ] Appendix slides prepared for Q&A.
- [ ] Fits allocated time slot.

## What "Not Done" Looks Like

A deliverable is not done if:
- Findings lack confidence tags.
- Sources are not cited.
- Limitations are not disclosed.
- The audience calibration is wrong.
- Quality gates have not been passed.
- The Research Director has not signed off.

## Handling "Almost Done"

If a deliverable is blocked from completion:
1. Identify the specific blocker.
2. Escalate per `escalation-rules.md` if time-critical.
3. Deliver with explicit caveats if partial delivery is approved.
4. Track the remaining items for completion.
