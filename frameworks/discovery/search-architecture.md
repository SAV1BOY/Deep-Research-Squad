# Search Architecture

## Purpose
A blueprint for designing a comprehensive search strategy. Maps each research question to the most appropriate source types, search tools, operators, and techniques. Ensures systematic coverage and prevents reliance on a single source or method.

## When to Use
- After the Question Tree has been built and leaves are ready for execution
- When research requires consulting diverse source types (academic, industry, data, expert)
- When search quality matters more than speed
- When previous searches returned poor or insufficient results

## Inputs
- Leaf-level questions from the Question Tree
- Known source types relevant to the domain
- Available search tools and databases
- Time budget per question

## Process

### 1. Map Questions to Source Types
For each leaf question, identify which source types are most likely to yield reliable answers:
- **Academic**: Peer-reviewed journals, preprints, conference proceedings
- **Industry**: Reports, white papers, analyst briefings, trade publications
- **Government**: Official statistics, regulatory filings, policy documents
- **News**: Investigative journalism, wire services, specialist outlets
- **Data**: Datasets, APIs, statistical databases, financial filings
- **Expert**: Interviews, testimony, professional forums, practitioner blogs
- **Primary**: Original documents, patents, court filings, internal records

### 2. Select Tools per Source Type
Match each source type to the best retrieval tool:
- **General web**: Google, Bing with advanced operators
- **Academic**: Google Scholar, Semantic Scholar, PubMed, JSTOR
- **Data**: Government data portals, Kaggle, World Bank, FRED
- **News**: News aggregators, LexisNexis, specialized archives
- **Industry**: Company investor relations pages, SEC EDGAR, industry databases
- **Social**: Reddit, Twitter/X, specialized forums for practitioner insight

### 3. Design Search Queries
For each question-source-tool combination, craft specific queries:
- Use exact phrases in quotes for precise matching
- Use Boolean operators (AND, OR, NOT) to refine scope
- Apply site-specific operators (site:, filetype:) to target sources
- Use date range filters to ensure recency or historical coverage
- Prepare fallback queries with broader or narrower terms

### 4. Define Search Sequences
Order searches to maximize efficiency:
- Start with broad reconnaissance searches to map the landscape
- Follow with targeted searches on specific sub-topics
- End with verification searches to cross-check key claims
- Plan iterative rounds: findings from round one inform round two queries

### 5. Set Quality Thresholds
For each question, define when you have enough:
- Minimum number of independent sources required
- Acceptable source quality levels (per the Evidence Rating framework)
- Stop criteria: diminishing returns, saturation, or time exhaustion

## Outputs
- A search plan mapping each question to sources, tools, and queries
- Prepared query strings ready for execution
- A sequence plan for executing searches in optimal order
- Quality thresholds for determining search completeness

## Common Pitfalls
- **Single-source reliance**: Using only one search engine or database creates blind spots. Always triangulate.
- **Generic queries**: Vague search terms return noise. Invest time in precise query design.
- **Ignoring source type diversity**: Academic sources alone miss practitioner reality. News alone lacks rigor. Mix source types.
- **No fallback plan**: When the first query fails, researchers often give up or go too broad. Design fallback queries in advance.
- **Recency bias**: Defaulting to recent results misses foundational work. Include historical searches where relevant.
- **Skipping the verification round**: Accepting first-found answers without cross-checking leads to unreliable conclusions.
