# Search Iteration Framework

## Purpose
A disciplined methodology for refining search queries through successive iterations, ensuring that each round of searching builds on what was learned in prior rounds. Prevents the common failure of running the same search repeatedly with minor keyword variations while systematically expanding coverage and closing information gaps.

## When to Apply
- When initial searches return too many irrelevant results or too few useful ones
- When the research topic spans multiple domains, terminologies, or source ecosystems
- When comprehensive coverage is required and a single search pass is insufficient
- When early results reveal that the initial query framing missed important dimensions
- When the topic uses different terminology across disciplines, geographies, or time periods
- When the information landscape mapping reveals sparse coverage that may be a search problem rather than an availability problem

## Core Principles
1. **Each iteration must have a purpose**: Never re-search without articulating what the previous round missed and why the new query should find it.
2. **Diverge before converging**: Early iterations should cast wide nets across different vocabularies and source types. Later iterations narrow and deepen.
3. **Results inform queries**: The best source of new search terms is the content found in previous searches, not abstract brainstorming.
4. **Diminishing returns are a signal, not a failure**: When new iterations stop producing novel relevant results, the search space is approaching saturation for that particular vector.
5. **Document the search trail**: Every iteration should be logged so that coverage gaps can be identified and the search is reproducible.
6. **Source diversity matters**: Iterating within a single database or search engine produces diminishing returns faster than iterating across different source ecosystems.

## Step-by-Step Methodology

### Step 1: Formulate the Initial Query
Construct the first search based on the research question, using the most obvious terminology. Key question: What terms would an expert in this domain use to describe this topic?

### Step 2: Execute and Assess Round One Results
Run the search and evaluate what came back. Key question: What did I find, what is missing, and what new terms or concepts appeared in the results that I did not anticipate?

### Step 3: Extract New Search Vectors
From the results, harvest new keywords, author names, publication venues, related concepts, and cited references. Key question: What language do the best sources use that differs from my initial framing?

### Step 4: Reformulate Queries for Round Two
Build new queries using harvested terms, synonyms, related concepts, or different source types. Key question: Am I searching a genuinely different slice of the information space, or am I repeating round one with cosmetic changes?

### Step 5: Assess Coverage Gaps
After each round, map what aspects of the research question are well-covered and which remain thin. Key question: Which sub-questions have strong source coverage, and which have little or no relevant material?

### Step 6: Target Gap-Filling Searches
Design queries specifically aimed at the weakest coverage areas. Key question: Is the gap due to using wrong terminology, searching wrong sources, or the information genuinely not existing?

### Step 7: Apply Saturation Test
Determine whether additional iterations are producing meaningful new information. Key question: Are the last two rounds surfacing sources I have already seen or trivially similar content?

### Step 8: Compile the Search Log
Document all queries run, sources consulted, and the rationale for each iteration. Key question: Could another researcher review this log and understand why these searches were chosen and what they covered?

## Output Format
- Search iteration log: query text, source/database, date, number of results, number of relevant results, key findings
- Coverage map: research sub-questions mapped to iteration rounds that addressed them
- Gap assessment: sub-questions with weak or no coverage and explanation (terminology gap, source gap, or genuine information void)
- Saturation statement: assessment of whether further searching is likely to yield material new information

## Integration with Other Frameworks
- **Query Strategist Expansion**: Provides the vocabulary expansion techniques used in reformulation steps.
- **Semantic Pivoting**: Pivot techniques are a specific tactic within the iteration framework for shifting between terminology domains.
- **Source Class Routing**: Different iterations may target different source classes to maximize coverage diversity.
- **Information Landscape Mapping**: The coverage map produced here feeds into the broader information landscape.
- **Keyword Grid**: The keyword grid is a tool used within each iteration to organize search terms.
- **Operator Matrix**: Boolean operator strategies from the matrix are applied within individual iterations to refine precision and recall.

## Anti-Patterns
- **Keyword treadmill**: Running dozens of minor keyword variations without changing the fundamental search strategy or source set.
- **One-and-done searching**: Running a single search, taking whatever comes back, and declaring research complete.
- **Ignoring what results teach**: Failing to read results carefully enough to extract new search vectors from the content itself.
- **Undocumented iteration**: Running multiple searches without logging them, making it impossible to assess coverage or reproduce the search.
- **Premature saturation declaration**: Concluding that the search space is exhausted when only one source type or terminology set has been explored.
- **Complexity escalation**: Making each successive query more complex and Boolean-heavy when simplification and term substitution would be more effective.
- **Platform loyalty**: Iterating exclusively within one search engine or database when different platforms index different content and would yield different results.
