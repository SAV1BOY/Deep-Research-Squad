# Issue Tree Framework

## Purpose
Decompose a complex research problem into a hierarchical structure of sub-questions, where each level breaks the parent question into mutually exclusive and collectively exhaustive components. Enables systematic investigation without gaps or redundant effort.

## When to Use
- After problem framing and scope bounding are complete.
- When a research problem has multiple interrelated dimensions.
- When the team needs to divide work across agents without overlap.
- When you need to identify which sub-questions carry the most information value.

## Inputs
- Validated problem statement.
- Scope boundaries (temporal, geographic, domain, depth, breadth).
- Any known constraints or hypotheses.

## Process

### Step 1: State the Root Question
- Write the core research question as a single, clear sentence.
- Ensure it is answerable (not rhetorical or philosophical).
- Confirm it aligns with the validated problem statement.

### Step 2: Identify First-Level Branches
- Break the root question into 3-7 sub-questions.
- Apply MECE: each branch covers a distinct aspect, all branches together cover the full scope.
- Use a decomposition logic: by component, by cause, by stakeholder, by time period, or by process step.
- Label the decomposition logic explicitly.

### Step 3: Decompose Each Branch
- For each first-level branch, repeat the decomposition into 2-5 sub-branches.
- Maintain MECE at every level.
- Stop decomposing when a question is directly investigable with a single source search or analysis.

### Step 4: Assess Depth — When to Go Deeper
- Go deeper when a sub-question is still too complex to answer directly.
- Go deeper when the sub-question carries high information value for the root question.
- Go deeper when initial evidence is contradictory and needs finer-grained investigation.

### Step 5: Assess Depth — When to Stop
- Stop when the sub-question can be answered with a single focused search.
- Stop when further decomposition would exceed scope bounds.
- Stop when the sub-question has low impact on the root question's answer.
- Stop at the maximum depth level defined in scope bounding.

### Step 6: Prioritize Branches
- Rank branches by expected information value (how much answering this changes the root answer).
- Rank by feasibility (can this actually be investigated with available sources?).
- Assign investigation order based on priority.

### Step 7: Validate the Tree
- Check MECE at every level: no gaps, no overlaps.
- Confirm every leaf node is actionable.
- Verify the tree respects scope boundaries.

## Outputs
- A structured issue tree (can be represented as nested list, diagram, or outline).
- Priority ranking of branches.
- Investigation order recommendation.
- Identified dependencies between branches.

## Common Pitfalls
- Non-MECE decomposition: overlapping branches cause duplicated work; gaps cause missed insights.
- Going too deep too early on low-priority branches.
- Using inconsistent decomposition logic across the same level.
- Creating leaf nodes that are still too broad to investigate directly.
- Treating the tree as fixed; it should evolve as evidence emerges.
- Decomposing beyond the point of usefulness (over-engineering the structure).

## Related Frameworks
- **Problem Framing**: The root question comes from the framed problem.
- **Scope Bounding**: Depth and breadth bounds constrain the tree.
- **MECE for Research**: The quality standard applied at every level.
- **Question Pyramid**: An alternative hierarchical structure for question organization.
- **Keyword Grid**: Leaf nodes feed into keyword generation for search.
