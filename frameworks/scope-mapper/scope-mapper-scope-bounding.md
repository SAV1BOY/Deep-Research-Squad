# Scope Bounding Framework

## Purpose
Set explicit, defensible boundaries on a research effort across multiple dimensions. Prevents scope creep, ensures efficient resource allocation, and makes inclusion/exclusion decisions transparent and reviewable.

## When to Use
- Immediately after problem framing, before any research begins.
- When a research question could expand indefinitely without constraints.
- When multiple agents need a shared understanding of what is in and out of scope.
- When revisiting scope mid-research because initial bounds proved too narrow or too wide.

## Inputs
- Validated problem statement from Problem Framing.
- Success criteria and required confidence level.
- Time and resource constraints.
- Any explicit user preferences on scope.

## Process

### Step 1: Define Temporal Bounds
- What time period does this research cover? (e.g., last 5 years, since 2020, historical.)
- Is recency critical or is foundational/historical context needed?
- Set a hard cutoff date and document the rationale.

### Step 2: Define Geographic Bounds
- Is the research global, regional, or country-specific?
- Are there jurisdictions or markets that must be included or excluded?
- Document geographic scope and any exceptions.

### Step 3: Define Domain Bounds
- Which disciplines, industries, or sectors are in scope?
- Are adjacent domains included for analogous evidence?
- List included domains explicitly and note excluded domains with reasons.

### Step 4: Define Depth Bounds
- How deep should the research go on any single sub-question?
- Set a maximum depth level (e.g., 3 levels of decomposition).
- Define the "good enough" threshold: when is a sub-question sufficiently answered?

### Step 5: Define Breadth Bounds
- How many parallel sub-questions should be pursued?
- Set a maximum number of branches to investigate simultaneously.
- Prioritize branches by expected information value.

### Step 6: Build Include/Exclude Criteria
- Create an explicit inclusion list: source types, evidence types, languages.
- Create an explicit exclusion list: out-of-scope topics, source types to avoid.
- Document edge cases and how they should be handled.

### Step 7: Set Review Triggers
- Define conditions that trigger a scope review (e.g., finding contradictory evidence, discovering an adjacent critical topic).
- Specify who can authorize scope changes and how they are documented.

## Outputs
- A scope boundary document with explicit bounds on all five dimensions.
- Include/exclude criteria list.
- Review trigger conditions.
- A one-paragraph scope summary for quick reference by all agents.

## Common Pitfalls
- Setting bounds too tight, missing critical context or evidence.
- Setting bounds too loose, leading to unbounded research and wasted effort.
- Failing to document exclusions, causing confusion about why certain topics were skipped.
- Not defining depth limits, allowing rabbit-hole investigations on minor sub-questions.
- Treating scope as fixed; it should be revisitable when evidence warrants it.
- Implicit scope: assuming all agents share the same mental model without writing it down.

## Related Frameworks
- **Problem Framing**: Scope bounding follows directly from the framed problem.
- **Issue Tree**: Depth and breadth bounds constrain how the issue tree is built.
- **MECE for Research**: Ensure bounded scope still covers the problem exhaustively.
- **Question Pyramid**: Scope bounds determine how many levels of questions to pursue.
