# MECE for Research Framework

## Purpose
Apply the MECE (Mutually Exclusive, Collectively Exhaustive) principle specifically to research question decomposition and evidence categorization. Ensures no research effort is duplicated and no critical area is overlooked.

## When to Use
- When building or validating an issue tree.
- When categorizing evidence into distinct groups.
- When dividing research work across multiple agents.
- When reviewing a research plan for completeness.

## Inputs
- A set of research sub-questions or categories to evaluate.
- The parent question or category they should collectively cover.
- Scope boundaries defining the universe of coverage.

## Process

### Step 1: Define the Universe
- Clearly state what "exhaustive" means in this context.
- The universe is bounded by the scope definition, not by all possible knowledge.
- Write a one-sentence description of the complete space to be covered.

### Step 2: Test for Mutual Exclusivity (No Overlap)
- Take each pair of categories or sub-questions.
- Ask: Could a piece of evidence or a finding legitimately belong to both?
- If yes, the categories overlap. Resolve by:
  - Sharpening definitions to create clear boundaries.
  - Merging overlapping categories into one.
  - Creating a decision rule for borderline items.
- Document the boundary between adjacent categories explicitly.

### Step 3: Test for Collective Exhaustiveness (No Gaps)
- List everything the parent question asks about.
- Map each element to one of the sub-categories.
- Ask: Is there any plausible finding that would not fit into any category?
- If yes, either add a new category or expand an existing one.
- Use a residual category ("Other") only as a last resort, and keep it small.

### Step 4: Choose a Decomposition Dimension
- MECE decomposition requires a single consistent dimension at each level.
- Common dimensions for research:
  - By topic or subject area.
  - By methodology or evidence type.
  - By stakeholder or perspective.
  - By time period.
  - By geography.
  - By causal mechanism.
- Mixing dimensions at the same level breaks MECE. Choose one per level.

### Step 5: Validate with Stress Tests
- Invent three hypothetical findings and try to classify them.
- If any finding falls into two categories or none, the structure fails MECE.
- Revise until all test cases classify cleanly.

### Step 6: Document and Communicate
- Write the MECE structure as a clear outline with category definitions.
- Include boundary rules for edge cases.
- Share with all agents who will use the structure.

## Outputs
- A validated MECE structure (categories or sub-questions).
- Boundary definitions between adjacent categories.
- Edge case handling rules.
- Confirmation that the structure passes stress tests.

## Common Pitfalls
- Confusing "comprehensive" with "exhaustive." Exhaustive means covering the defined universe, not all knowledge.
- Using overlapping labels that seem distinct but cover the same ground (e.g., "market trends" vs "industry dynamics").
- Relying on a large "Other" category, which signals the decomposition is incomplete.
- Mixing decomposition dimensions at the same level (e.g., splitting by geography and by topic at the same level).
- Treating MECE as a one-time check rather than an ongoing validation as the research evolves.
- Over-fragmenting: creating so many categories that the structure becomes unwieldy.

## Related Frameworks
- **Issue Tree**: MECE is the quality standard applied at every level of the tree.
- **Problem Framing**: The framed problem defines the universe for exhaustiveness.
- **Scope Bounding**: Scope boundaries limit what "exhaustive" means.
- **Question Pyramid**: MECE applies to the relationship between mother and daughter questions.
- **Source Class Routing**: MECE can be applied to source categorization.
